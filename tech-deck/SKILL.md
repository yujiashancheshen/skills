# Tech Deck — 技术演示文稿生成

把技术内容变成业内顶尖水准的 HTML 演示文稿。零依赖、单文件、浏览器直接打开。

## 核心原则

1. **诊断先行**：拿到内容先判断宣讲对象、目的、是否需要联网补料、是否要演讲稿。能从内容推断的自己推断，只把关键项集中问一轮。见步骤 0。
2. **叙事先行**：先定"怎么讲"再谈"怎么排版"。像推荐模板一样主推 1 套叙事框架 + 理由。见 `templates/_叙事结构.md`。
3. **AI 推荐先行**：模板不让用户硬选。AI 分析内容气质，主推 1 套模板 + 备选 1 套，说明理由。
4. **大纲确认**：生成前必须逐页确认内容+版式，且每页标注一句话 take-away，用户可逐页调整。
5. **内容铁律**：先具体后解释、用证据代替形容词、标题是观点、禁用套话。见 `templates/_叙事结构.md`。
6. **模板 = 完整视觉语言**：色彩 + 空间 + 字体 + 偏好版式 + 动画 + 翻页，不是单纯配色。
7. **布局质量铁律**：必须像业内顶尖 PPT —— 大字号、每页一焦点、重点高亮、留白优先。见 `templates/_布局铁律.md`。
8. **逐页选版式**：版式与模板正交，每页可独立选。见 `templates/_版式目录.md`（约 23 种）。
9. **自动校验**：生成后用 Playwright 截图验证 **1920×1080** 无溢出（默认只测此分辨率提速，多分辨率基本不常用）。
10. **零依赖**：单 HTML 文件，内联 CSS+JS，字体仅 Google Fonts。

## 6 套模板（完整视觉语言）

每套都是经过调校、对标业内顶尖产品的完整体系。规格见 `templates/<名>.md`，效果样例见同名 `templates/<名>.html`。

| 模板 | 对标 | 气质 | 适合 |
|------|------|------|------|
| 暗夜微光风 | Linear/Vercel | 暗色高级、科技发布会 | AI、基础设施、技术战略 |
| 清晰商务风 | Stripe | 金融级信任、明亮专业 | 产品发布、商业汇报、路演 |
| 杂志墨刊风 | Kinfolk杂志 | 文艺有格调、深度叙事 | 技术演讲、思考型分享 |
| 极简黑白风 | Apple Keynote | 极致对比、自信有力 | 发布、立场宣言 |
| 暖意画布风 | Notion/Things | 柔性极简、温暖亲和 | 产品概览、团队分享 |
| 极光未来风 | AI 产品 | 未来感、惊艳 | AI 产品、前沿技术 |

## 工作流程

```
0. 诊断问答 → 判断宣讲对象/目的/长度/是否联网补料/是否要演讲稿；智能推断，只问关键
1. 叙事框架 → 主推 1 套讲法 + 理由（金字塔/SCQA/问题-方案-收益/What-Why-How/故事线）
2. AI 推荐  → 主推 1 套模板 + 备选 1 套，说明理由；只生成主推预览（要看备选再生成）
3. 列大纲   → 逐页列出标题、内容、推荐版式 + 一句话 take-away；用户可逐页调整
4. 生成     → 读取模板规格 + 版式目录 + 布局铁律 + 内容铁律，构建完整 HTML
5. 校验     → Playwright 截图检查无溢出
6. 交付     → 打开文件，删除预览，说明定制方法
7. 演讲稿   → （可选）确认风格/时长后，生成逐页口语讲解稿
```

### 步骤 0：诊断问答（智能推断，只问关键）

拿到内容先自己推断能推断的（主题、气质、大致篇幅），**只把无法确定的关键项集中问一轮**，别逐条盘问。核心要问清 5 件事：

1. **宣讲对象是谁**：高管/同行工程师/客户/投资人/团队内部/大会听众——决定叙事框架、深度、语言。
2. **演讲目的**：说服/教学/汇报/发布/激励。
3. **长度偏好**：短（5-10 页）/中（10-20）/长（20+）。
4. **是否需要联网补料**：内容是否够撑满演示，要不要补数据、案例、竞品、最新进展（见下方"联网扩展"）。
5. **是否需要配套演讲稿**：要不要在演示之外附一份逐页口语讲解稿（见步骤 7）。

能从已给内容合理推断的，就在提问里写明"我推断是 X，对吗"，减少用户负担。宣讲对象和目的确认后，据此选叙事框架（步骤 1）。

### 步骤 0.5：联网扩展外部信息（默认先问）

判断内容是否偏单薄（缺数据支撑、缺真实案例、缺竞品对比、涉及会过时的进展）。**默认先问用户是否需要联网补充**，得到同意再检索；用户说不用就只用已有内容。

- 补充的每条外部信息都要能追溯来源，写进大纲时标注出处。
- 绝不为了填页而编造数据或案例（见内容铁律第 6 条）。

### 步骤 1：叙事框架提案（怎么讲）

根据宣讲对象和目的，从 `templates/_叙事结构.md` 的框架库里**主推 1 套讲法**，用一句话说清为什么这样讲（例如"对象是高管、目的是拿预算 → 用金字塔原理，结论先行，先给要什么再给依据"）。用户可换框架。

框架定了之后，它决定大纲的骨架顺序（哪页承担情境、哪页承担转折/结论），再进入模板与版式。

### 步骤 2：AI 推荐模板（不全量预览）

**关键改进：不再 6 套全生成预览让用户挑。**

基于内容气质分析，AI 主动推荐：
- **主推 1 套** + 一句话理由（为什么这套最契合）
- **备选 1 套** + 一句话理由（什么情况下选它）

只为**主推**生成一个 4 页预览 HTML 放 `preview/`，打开给用户看。
用户想看备选，再生成备选预览。用户认可主推，直接进下一步。

推荐逻辑参考：
- AI/技术战略/暗色高级 → 暗夜微光风
- 对外商业/产品发布/明亮可信 → 清晰商务风
- 深度演讲/思考叙事 → 杂志墨刊风
- 立场宣言/强冲击 → 极简黑白风
- 团队内部/温暖轻松 → 暖意画布风
- AI 产品/惊艳前沿 → 极光未来风

### 步骤 3：列大纲（逐页版式 + take-away，必须确认）

按选定叙事框架排页序，展示完整大纲。**每页标注推荐版式**（版式标识见 `templates/_版式目录.md`）**并加一行 `记住：<一句话 take-away>`**，让用户在生成前审阅每页的核心信息，而不只是版式：

```
幻灯片大纲（共 X 页，模板：XXX，叙事：问题-方案-收益）：

第 1 页 [hero 封面]
  标题：XXX  副标题：XXX
  记住：这场演讲要解决的那个痛点

第 2 页 [stat-hero 数据英雄]
  核心数字：XXX  说明：XXX
  记住：痛点有多严重（量化）

第 3 页 [cards 卡片网格]
  标题：XXX
  • 卡1 …  • 卡2 …  • 卡3 …
  记住：方案的三个支柱

...（逐页）
```

用户可逐页调整："第 3 页换成 dash 数据仪表"、"加一页 quote"、"删掉第 5 页"、"第 2 页的重点改成 X"。
**确认后才生成。绝不在未确认大纲时直接生成。**

### 步骤 4：生成

读取四份规格：
1. 选定模板 `templates/<名>.md`（色彩/字体/空间/出彩点/动画），可参考同名 `.html` 样例
2. 版式目录 `templates/_版式目录.md`（每页对应版式的结构）
3. 布局铁律 `templates/_布局铁律.md`（大字号/焦点/高亮/留白）
4. 叙事结构 `templates/_叙事结构.md`（内容撰写铁律：先具体后解释、证据代替形容词、标题即观点、禁用套话）

构建完整 HTML，含：语义化 slide、视口安全 CSS、键盘/触摸/滚轮导航、IntersectionObserver 错落淡入、`prefers-reduced-motion`、进度条+页码+导航点。

**输出目录**：若输入内容来自某个文件（如 `.md`/`.txt`/`.pptx`），输出到**该文件所在的同一目录**；否则输出到用户当前工作目录。文件名 `[主题]-[模板].html`。

### 步骤 5：自动校验

**默认只校验 1920×1080**（演示主场景）。截图检查：无溢出滚动条、导航可用、文字不截断重叠。发现问题自动修复重校验。

多分辨率（1280×720 / 768×1024 / 375×667 / 667×375）基本不常用,**默认忽略以提速**;仅当用户明确要求适配移动端/多端时才补测其余分辨率。

Playwright 不可用时做结构检查：每个 `.slide` 有 `100vh/100dvh/overflow:hidden`、字号用 `clamp()`、无固定高度容器。

### 步骤 6：交付

删除 `preview/` 临时文件 → 打开 HTML（macOS `open`）→ 告知：文件路径、模板名、页数、改主题色的 CSS 变量、操作方式。

若步骤 0 未提及演讲稿，交付时可主动问一句"要不要配一份逐页演讲稿"。

### 步骤 7：演讲稿（可选）

仅当用户需要时执行。规范见 `templates/_演讲稿.md`。要点：

1. **两道确认**：步骤 0 已确认"要不要"；写稿前再确认**风格 / 时长 / 是否含 Q&A 预案**，能推断的写明"我按 X 来，对吗"，确认后才动笔。
2. **逐页对应**：每页幻灯片对应一段讲解（引导句 → 核心讲解 → 过渡句），开头有总述、结尾有收束，密集页加演讲提示。
3. **口吻随对象**：与幻灯片同一宣讲对象保持一致（新人多铺垫、高管重结论）。
4. **不编造、能对着念**：只展开演示与原文已有信息，联网补充要标注来源，口语化短句。
5. **输出**：`[主题]-演讲稿.md`，与演示 HTML 同目录（遵循步骤 4 输出目录规则）。

## 参考文件索引

- `templates/_叙事结构.md` — 叙事框架库（5 种，按对象推荐）+ 内容撰写铁律（强制）
- `templates/_版式目录.md` — 约 23 种版式目录（逐页选）
- `templates/_布局铁律.md` — 布局质量铁律（强制）
- `templates/_演讲稿.md` — 演讲稿规范（可选产出：确认过程 + 结构 + 口吻 + 输出）
- `templates/<名>.md` 6 个 — 模板完整规格；同名 `.html` 为效果样例

## 反模式（禁止）

- 跳过诊断直接开做（应先判断对象/目的/是否补料，只问关键项）
- 跳过叙事框架直接排版（应先定"怎么讲"，主推 1 套 + 理由）
- 大纲只标版式、不标每页 take-away（用户看不到核心信息）
- 内容单薄时不问就硬填，或为凑页数编造数据/案例
- 标题写成名词标签（"缓存优化"）而非观点（"缓存让延迟降了 85%"）
- 满页套话（"在当今快速发展的时代""赋能""闭环"）、用形容词代替证据
- 把模板做成"只换配色"（必须是完整视觉语言）
- 字太小（正文 < 0.95rem）、内容平铺无焦点、全灰字无高亮
- 6 套全量预览才让用户选（应 AI 推荐主推+备选）
- 未确认大纲就生成
- 未确认风格/时长就直接写整篇演讲稿；或演讲稿只是照抄屏幕文字、编造问答
- 超长文字墙、需滚动的代码块、固定高度容器
- 紫白渐变通用模板、Inter/Arial 当主视觉（除非模板指定）
