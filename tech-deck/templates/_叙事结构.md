# 叙事结构与内容铁律（生成前必读）

视觉再好，讲不清也是失败。这份文件解决"怎么讲"——先定叙事骨架，再谈每页版式。

---

## 一、叙事框架库（主推 1 种 + 说明理由）

像推荐视觉模板一样：分析宣讲对象和目的，**主推 1 套讲法**，一句话说清为什么这样讲，用户可换。

### 1. 金字塔原理（结论先行 / BLUF）
先抛结论和建议，再分点支撑，最后才是细节。
- **适合**：公司高管、决策层、时间紧的听众——他们要的是"所以我该做什么"。
- **骨架**：核心结论/建议 → 3 条支撑论据 → 每条的证据/细节 → 行动项。

### 2. SCQA（情境-冲突-问题-答案）
麦肯锡经典。先建立共识，再引出张力，最后给答案。
- **适合**：对上汇报、需要先对齐背景再给方案的场景。
- **骨架**：情境（大家都认同的现状）→ 冲突（出现了什么变化/问题）→ 问题（我们要回答什么）→ 答案（我的方案）。

### 3. 问题-方案-收益（Problem-Solution-Benefit）
先戳痛点，再给方案，用量化收益收尾。
- **适合**：产品发布、对外推介、投资路演、任何说服型演讲。
- **骨架**：痛点（有多痛、多频繁）→ 方案（怎么解决）→ 收益（量化结果）→ 差异化（为什么是我们）。

### 4. What-Why-How
是什么 → 为什么这样设计/为什么重要 → 怎么做/怎么用。
- **适合**：技术分享、同行评审、教学、团队内部——听众关心设计权衡和落地。
- **骨架**：概念/背景 → 设计动机与取舍 → 架构/实现 → 使用与效果 → 坑与经验。

### 5. 故事线 / 英雄之旅
用叙事张力带动情绪：现状 → 挑战 → 转折 → 新世界。
- **适合**：大会主题演讲、愿景宣讲、激励型分享——要的是记忆点和共鸣。
- **骨架**：熟悉的现状 → 遇到的挑战 → 关键转折/洞察 → 展现新世界 → 一句话记忆点。

### 按宣讲对象快速推荐

| 宣讲对象 | 首选框架 | 理由 |
|----------|----------|------|
| 公司高管 / 决策层 | 金字塔原理 / SCQA | 时间紧，要结论和依据 |
| 同行工程师 / 技术评审 | What-Why-How | 关心设计权衡与实现细节 |
| 客户 / 投资人 | 问题-方案-收益 / 故事线 | 要被说服、要看到价值 |
| 团队内部 | What-Why-How / 故事线 | 轻松，重共识与共鸣 |
| 大会主题演讲 | 故事线 / 英雄之旅 | 要记忆点和情绪 |

## 二、内容撰写铁律（每页文案强制遵守）

借鉴顶尖长文写作的硬规则，避免"AI 味"和空洞演示。

1. **每页一个 take-away**：一句话能说出"这页要听众记住什么"。说不出，就是这页没想清楚，拆或删。
2. **先具体，后解释**：先抛具体的东西（数字、示例、截图、demo、代码），再解释含义。不要先铺三行概念。
3. **用证据代替形容词**：不说"性能大幅提升"，说"P99 从 800ms 降到 120ms"。不说"广受好评"，给数据或引用。
4. **标题是观点，不是标签**：用"缓存让延迟降了 85%"，而不是"缓存优化"。让人扫一眼标题就知道结论。
5. **禁用套话**：删掉并重写——"在当今快速发展的时代""颠覆性""游戏规则改变者""赋能""打造闭环""众所周知"以及任何拖延重点的开场客套。
6. **不编造**：数据、案例、客户证言不得虚构。缺料就联网补（见 SKILL.md 步骤），或如实标注为示例。

## 三、大纲里怎么体现

在"列大纲"步骤，每页除了标注推荐版式，**必须再加一行 `记住：<一句话 take-away>`**，让用户在生成前就能审阅每页的核心信息，而不只是版式。
