# 程序员画图（技术配图生成）

把技术内容变成专业好看的配图。核心思路：**不让用户硬写提示词**，而是选一套打磨好的模板、填空、调出图 API。

## 核心原则
目标用户**审美不行、说不清要什么风格**。所以**默认由你（模型）替他决定风格**，不要一上来就甩"你想要哪种风格"这种他答不上来的问题。用户只管丢内容，你负责出好图。

## 质感铁律（所有风格通用，最容易翻车的一条）
出图最常见的失败是**"很平"**——平铺的图标+圆角卡片网格、没有视觉主角、所有元素压在一个平面，一眼就是廉价 AI 信息图。**每张图都必须做到**：
1. **有一个视觉主体(hero)**：一个立体的、有体积/质感的主角元素，是全图的视觉中心（如处理装置、核心架构、关键数字、主角色）。
2. **有纵深**：柔和渐变背景 + 层次投影，让元素"浮起来"，不是压在一个平面。
3. **用隐喻组织信息**：用物理容器/场景（大脑、管道、平台、水桶…）承载内容，而不是把词塞进格子。
4. **图标/元素精致有插画感**，风格统一，不是通用线性图标。
> 适配：data-card（数据卡片风）的图表保持干净精确、不做廉价3D，但卡片要抬起有体积、要有立体 hero 装置和插画图标；sketch-note（手绘涂鸦风）的质感来自手绘笔触而非体积；fresh-flow（清新流程风）的质感来自清爽的多彩分段+泳道编排+咬合箭头+干净留白，不追求立体 hero，但靠色彩节奏、卡片细描边轻投影与分明层级撑起精致感，绝不允许脏乱、色彩打架、密到无留白。填模板时务必保留各模板里这部分的描述词。**任何风格都不允许"压在一个平面的扁平卡片网格"。**

## 工作流程（严格按顺序）

### ① 选风格（默认你来定，别让用户硬挑）
只需要用户提供：**①要画的内容/主题 ②大概用在哪、给谁看（可选）③想要的气质（可选，如"高级酷炫""轻松有梗"）**。

然后**由你根据内容特征匹配风格**，按下表判断，直接选定并一句话说明理由，进入下一步：

| 风格 | 模板文件 | 样图 | 适合的内容 |
|---|---|---|---|
| **科技插画风** | `templates/科技插画风.md` | `templates/科技插画风.png` | 流程、转化链路、能力分层、"从A到B"。专业有质感（有 hero+纵深，不是扁平网格） |
| **暗色科技风** | `templates/暗色科技风.md` | `templates/暗色科技风.png` | 架构、AI、安全、性能、底层系统。想要酷炫高级 |
| **等距立体风** | `templates/等距立体风.md` | `templates/等距立体风.png` | 系统架构、基础设施、技术栈分层、部署拓扑。立体有空间感 |
| **数据卡片风** | `templates/数据卡片风.md` | `templates/数据卡片风.png` | 指标、数据、对比、榜单、benchmark、要点总结。强调数字 |
| **手绘涂鸦风** | `templates/手绘涂鸦风.md` | `templates/手绘涂鸦风.png` | 观点、踩坑、认知反差、金句传播。轻松有梗 |
| **清新流程风** | `templates/清新流程风.md` | `templates/清新流程风.png` | 多阶段业务流程、服务链路、SOP、用户旅程、运营 playbook。信息量大、要分阶段+分泳道+带循环。干净小清新、专业商务 |

> 每个模板文件顶部都内嵌了对应**样图**（同名 `.png`），不确定某风格长啥样时，先看模板里的样图。

匹配指引：偏流程链路→科技插画风；偏架构/系统且要酷→暗色科技风；偏分层/基础设施/立体→等距立体风；偏数字/对比→数据卡片风；偏观点/吐槽→手绘涂鸦风；偏多阶段复杂流程/服务链路/SOP/用户旅程（信息量大、要分阶段+分泳道+带循环）→清新流程风。
> 科技插画风 vs 清新流程风的区别：前者是"单线 A→B + 一个立体 hero 主视觉"，信息量小、重质感；后者是"多阶段+多泳道+可闭环的复杂编排"，信息量大、重清爽清晰的结构组织。
> **三种入口**：①「我全权决定，只要好看」= 默认，你直接选并说明理由 ②用户给了气质偏好 → 你据此选 ③懂行用户直接点名风格 → 用他指定的。无论哪种，都不要把选择的负担硬压回给说不清的用户。
> 拿不准时可同时给出 1 个主推 + 1 个备选，让用户一句话拍板即可，而不是让他从 5 个里盲选。

### ② 读模板 + 收集槽位
读取选中的模板文件，按其中「需要向用户收集的槽位」表，**一次性把缺的信息问清楚**（用 AskUserQuestion 或直接列出来让用户补）。不要一个一个挤牙膏。

### ③ 填模板，生成最终提示词
把用户内容替换进模板的「提示词骨架」。替换后**通读一遍**：
- 所有 `{{}}` 都已替换，没有残留
- 文字标签简洁、无歧义
- 保留模板里的风格描述词（palette、texture、ratio 等灵魂不能丢）

把拼好的完整提示词**先展示给用户确认**，再出图。

### ④ 调用出图脚本
```bash
python skills/programmer-illustration/scripts/generate.py \
  --prompt "<填好的完整提示词>" \
  --ratio "<模板里的 ratio，如 16:9 或 3:2>" \
  --style "<风格中文名，如 科技插画风>" \
  --title "<图的主标题，如 实时风控决策引擎>" \
  --provider "<可选：openai | gemini | doubao | qwen，默认读 config 的 active>"
  # 不传 --out 时，默认在当前工作目录生成「风格-标题.png」；也可用 --out 指定文件名或路径
```
- 脚本**自包含**：配置读 skill 内的 `config.json`（复制 `config.example.json` 改名，把 `active` 设成要用的通道并填它的 key），model/base_url 已内置各家官方默认；路径相对脚本自身定位，在哪个目录调用都能找到配置。
- 支持 4 个 provider：**openai(gpt)、gemini、doubao(火山方舟/Seedream)、qwen(qwen-image)**。用哪个就在 config 的对应通道填 key，并把 `active` 设成它（或用 `--provider` 临时指定）。
- 出图默认落在**调用脚本时的当前工作目录**，文件名由 `--style` + `--title` 拼成（如 `科技插画风-实时风控决策引擎.png`），重名自动加序号；传 `--out` 可覆盖。
- 脚本失败时，把报错原因清楚告诉用户（多半是没填 key：复制 `config.example.json` 为 `config.json`，设好 `active` 并填该通道的 key）。

### ⑤ 自我批判 + 展示 + 微调
出图后**先自己对照下面这张清单逐条挑刺**，不合格就直接重跑，别把半成品丢给用户：

- [ ] **配色**：是否严格落在模板钉死的色板里？有没有冒出计划外的鲜艳色/脏渐变？
- [ ] **文字**：所有文字清晰可读、无错字乱码、不压边、不重叠？（中文出图最容易翻车，重点查）
- [ ] **风格统一**：图标/线条/字体是否同一套风格？有没有混搭违和？
- [ ] **AI 味**：是否避开了模板"反 AI 味护栏"里列的那些廉价感？
- [ ] **留白与对齐**：构图是否对齐、间距均匀、留白舒服，不挤不乱？
- [ ] **匠人感**：整体像不像专业的人精心打磨的，而不是随手生成？

任一条不过 → 改对应槽位/措辞，重跑。再把过关的图给用户看。
若用户要调：改文字/配色/构图就改对应槽位重跑；整体不对就回到 ① 换风格。一次不满意就多跑两版。

## 如何扩展新风格
1. 在 `templates/` 加一个新的 `.md`（中文名即可），照抄现有模板的结构（frontmatter + 样图引用 + 风格特征 + 槽位表 + 提示词骨架 + 示例）；放一张同名样图 `.png` 在 `templates/` 下
2. 在本文件 ① 的表格里加一行（含样图列）
不用动脚本和主流程。

## 注意
- 我（模型）本身不能直接出图，必须靠 `generate.py` 调外部 API
- 中文文字多、结构复杂的图，优先用 gemini（中文最准、指令遵循最好）；其次 doubao（构图美但中文偶有错字）。见 README
- 永远先让用户确认提示词再花钱出图
