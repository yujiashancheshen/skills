# 微信公众号可粘贴 HTML

这是 `wx-writer` 的默认 HTML 输出规范。生成的 `<slug>.html` 应能从浏览器中复制渲染后的正文，再粘贴到微信公众号编辑器。除非用户明确要求且在生成前同意，不要另外生成普通网页版。

## 为什么需要兼容版

微信公众号编辑器可能过滤 `<style>`、CSS class、页面级背景和部分布局属性。黑底浅色字尤其危险：外层黑色背景被过滤后，浅色正文会在白底上几乎不可见。

兼容版的目标是粘贴后稳定可读，不是像素级复制独立网页的效果。

## 样式约束

- 使用白色或接近白色的页面背景，禁止整篇黑底
- 正文使用深灰色，例如 `#333333`，不使用白色或低不透明度浅色文字
- H2 可保留橙色重点，但要在白底上有足够对比度
- H3 使用较深的橙褐色，可用左侧实线边框表示层级
- 只有正文中自然成立的金句候选才做视觉强调，可使用深蓝色加粗，但不依赖 class 才能显示样式；没有候选时不强行标注
- 代码块使用浅灰底、深色字和浅色边框，允许水平换行，不依赖深色主题
- 表格使用浅色实线边框、深色文字和浅灰表头，避免仅靠背景色区分单元格
- 对比区不使用 Grid 或 Flex。优先使用普通表格；内容较长时改成上下排列
- 公式或核心结论使用浅色边框和浅背景，不使用浮动、绝对定位或阴影表达层级
- 正文容器最大宽度可保留 677px，但不依赖媒体查询

## HTML 实现约束

- 把所有可见样式写到元素的 `style` 属性中
- 不使用 `<style>`、外部 CSS 或 CSS class 承载必要样式
- 不使用 Grid、Flex、媒体查询、粘性定位、绝对定位或依赖 JavaScript 的布局
- 优先使用 `section`、`p`、`h1`-`h3`、`blockquote`、`ul`、`ol`、`table`、`pre`、`img` 等简单标签
- 不得修改文章文字、标题序号、表格数据、代码和内容顺序

## 图片处理

- 保留文章中的图片位置和替代文字
- 本地 `file://` 图片不能作为可发布地址，交付时列出需要在公众号中重新上传的图片
- 图片设置 `max-width:100%`、`height:auto`、`display:block`，避免超出正文宽度
- 不把文章图片转成 base64 来规避公众号上传流程

## 检查与交付

生成后在桌面和窄宽视口检查：

- 白色背景上所有文字都清晰可见
- 标题、正文、金句、表格、代码块和图片没有溢出或重叠
- 即使 class 被全部删除，必要样式仍然存在
- 没有必须依赖页面级黑色背景才能读取的文字

交付时告诉用户：

1. 在浏览器中打开 `<slug>.html`
2. 复制浏览器中渲染出来的文章正文，不要复制 HTML 源码
3. 粘贴到微信公众号编辑器
4. 如图片没有被接收，在原位置重新上传对应图片
5. 分别检查电脑预览和手机预览，重点看代码块、表格、行距和图片宽度
6. 不要在公众号编辑器中全选后重新设置字体或颜色，避免覆盖已粘贴的内联样式
